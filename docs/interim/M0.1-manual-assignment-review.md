# Interim Manual Process — Assignment Review

**Status:** Active while the `assignment:auto-end-expired` scheduler is disabled.
**Started:** Phase 0 / Milestone M0.1.
**Ends when:** Phase 2 (Domain Core) ships the corrected eligibility logic and the scheduler is re-enabled (IMPLEMENTATION_PLAN.md, Milestone M2.5).
**Owner:** HSSE staff (`job_title = HSSE`), reviewed daily until Phase 2 ships.

## Why this exists

The nightly `assignment:auto-end-expired` command has been disabled
(`app/Console/Kernel.php`). It checked "does an *expired* SIO or SILO exist for
this operator/equipment?" instead of "does *no valid* SIO/SILO exist?". Because
expired documents are intentionally kept for audit history, any operator or
equipment that has ever had a document renewed ends up with one expired
document on file *and* one valid one — and the command was ending their
assignment anyway, every night, silently. See TECHNICAL_AUDIT.md finding **C1**
for the full analysis.

Disabling the command stops that damage immediately, but it also means
assignments that **genuinely should** end (operator or equipment with **no**
valid document at all) will no longer end automatically. This document is the
manual replacement until the real fix ships.

## Daily procedure

1. Open the **Alat Berat** panel in Filament and, for each equipment record,
   review the **Operator Assignments** tab.
2. For an assignment to be a genuine candidate for ending, **both** of the
   following must be true — check both, not just one:
   - The operator has **no SIO** with `tanggal_expired >= today` (i.e. every
     SIO on file for that operator is expired — not just *some* of them).
   - The equipment has **no SILO** with `tanggal_expired >= today` (same
     check, for SILO).
   The **Dokumen Expired** dashboard widget is a useful starting point to find
   candidates, but always confirm against the operator's/equipment's full
   document list before acting — the widget shows expired documents, not
   whether a *valid* replacement already exists.
3. If, and only if, both checks in step 2 hold, use the existing **"End"**
   action on that assignment row (sets `tanggal_selesai` and marks the
   assignment inactive) — the same action already available to HSSE staff in
   the Operator Assignments relation manager. Record the reason (which
   document expired) alongside the date you end it, since the automated
   command normally logs nothing either (TECHNICAL_AUDIT.md finding H5) — a
   short note here is the only trail until Phase 4 (Observability) adds
   proper logging.
4. Do **not** end an assignment solely because an expired document exists for
   that operator or equipment — check for a valid replacement first. Ending an
   assignment that still has a valid document is the exact mistake this
   interim process exists to avoid.

## What NOT to do

- Do not re-enable the scheduler manually as a shortcut. Its logic is still
  wrong; re-enabling it reintroduces C1.
- Do not write a new script or command to automate this check. A correct,
  single-source-of-truth implementation is coming in Phase 2
  (`DocumentValidity` value object, IMPLEMENTATION_PLAN.md Milestone M2.2) —
  a second manual implementation now would create exactly the kind of
  duplicated validity logic the audit and architecture documents flag as the
  root cause (TECHNICAL_AUDIT.md, "Duplikasi #1"; ARCHITECTURE_BLUEPRINT.md,
  Principle P3).
